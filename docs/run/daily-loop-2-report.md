## How it is put together

- **One table, personal** (`weekly_closeouts`, 0174): the row's space is the reader's own personal space and nothing else, the shape the interruptions ledger has (0161). One row a person a week (unique index). Registered as `platform.closeouts`; the registry test knows it. The lane applied it to the shared local stack through psql and recorded it in the migration history, because another lane had already pushed 0178 and the CLI then refuses `db push` for a lower number — the integrator pushes it to hosted as usual.
- **The fill is counted, never a streak** (rule 25). A week is "0 win days", never "lost"; the lifetime totals only grow. The week's fill and totals are frozen on the row when the week closes, so a plan edited later does not rewrite history.
- **The section raised comes from the dormant marks as they are** (`featureStatesFor` → `goneQuiet`), minus what has been settled: a pause for four weeks, a retirement until the feature's own tables show use after it. The dormant card and the dimmed navigation are unchanged by a decision: a paused feature is still quiet, it is simply not asked about.
- **The measures are read, not kept.** Start latency is the morning pick (accepted, else prompted, else proposed) to the first Start; return time is the gaps between days with something finished; nudge response reads `acted_at` on the ledger, which the close, the close-out and the finish line already write. Nothing was added to the loop to make them measurable.
- **The notices live in the daily-prompts job** already on the tick every five minutes 06:00–24:00, not a new schedule entry. Dedupe is by kind (`notice10`, `notice2`, `closeout`) and ticket on today's ledger rows. The budget gained one flag (`switchNotice`) that passes only the focus gate; quiet, budget and repeat still hold. Tested on `decide` directly.
- **The group handler takes its Telegram and its answerer as arguments**, so the unit tests run every bot against the same update through a fake and check who posted, as whom, and that two answering reply to the message so the thread reads. The real deps look up each bot's username once per warm instance.
- **No new dependency, no `next build` in the lane, nothing sub-daily in `vercel.json`.**

## Phil's live check (a chunk for MYC-193, 20 minutes; the integrator numbers it)

1. Settings → Today → **The week — when it closes**: set the day and time to a slot you will keep. Ten minutes before it, one notice arrives (*The week's close-out starts in 10 min.*), counted as one of the day's three.
2. Review → **Close the week**. Type one line for what the forty-five minutes will do, Begin. The box counts down; *This week* and *Lifetime* read right against what you remember of the week (win days, finished of started; the totals).
3. The **Gone quiet** card on the close-out names the one section with the biggest gap and asks why. Write a sentence and press Keep, Pause or Retire. Open the dashboard: the section is still marked quiet there (a decision changes the question, not the marks). Next week it is not asked about again (four weeks for a pause).
4. If anything is above 80% done and untouched for a fortnight, it is a card: Finish / Good enough / Drop. Swipe one.
5. Type the week's Screen Time from the phone, one line for how it went, **Close the week**. Reload: *Week closed.*, the report under it. Close it again: nothing changes.
6. **The first close-out of December** shows *The month, measured*: eight rows for November beside a dash column (no October), and the two questions with Kirsty under the report box. Answer them; they are kept on the row and read back the month after.
7. Give any ticket a time today ten or so minutes ahead (Work → the ticket → a time). Two lines arrive, one from about ten minutes out, one from about five, each with the true gap; on the Today card a running timer says *Ten minutes left.* and *Two minutes left. Find a stopping place.* at those marks. Start a timer first and the ticket's notice still arrives; a morning briefing would not.
8. **The Boys' group** is MYC-203: seven bots from BotFather, one group, eight env names, one POST to the setup route. Then in the group: *Coach, what's tomorrow's session?* answered by the Coach's bot as itself; *Morning all* by Da Boi alone; a spending question by The Advisor; a reply to a bot's message by that bot.
