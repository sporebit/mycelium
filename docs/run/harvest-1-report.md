## How it is put together

- **Tabs are URLs.** `resolveTab()` picks the first tab when `?tab=` is absent or names nothing; `tabHref()` gives the first tab the page itself and the rest `?tab=`. A tab may be its own route (Teams), so the sidebar can light it. The people page body moved into `components/settings/PeopleAndTeams.tsx` because a page file may export only its page, and two routes render it. The `Sheet` on the touch Settings page portals out of the page, so it is kept to touch widths by a media query (`lib/hooks/useMediaQuery.ts`), not by a class.
- **The sub-page lit is the longest match.** `activeSubPageHref()` in `lib/nav/sections.ts` and `placeForPath()` in `lib/home/menu.ts` replace three copies of `pathname.startsWith(href + "/")`, which lit the parent as well as the child. The sidebar's lit sub-link now carries `aria-current`.
- **The grid's spans live in `lib/dashboard/spans.ts`** so the breakpoint mapping is a pure function with a test. Desktop keeps the configured span for every size; the tablet span is `width × 2` of six columns, which keeps the three widths three widths. The row height, the dense flow, drag and the size picker are as they were.
- **`ai_models` is instance-level**, not a space table: the providers are the instance's. Read by the instance owner only (the policy is `app.is_instance_owner()`, as profiles in 0102); written only by the cron as service role. It is not adopted and not in the access registry for that reason, like `profiles`.
- **A retirement is a fact seen, never a guess.** Only a successful fetch retires, and only what it did not list. A failed call is an error, not an empty list (an empty list would retire everything). A retired model the provider lists again comes back, and a later retirement is news again.
- **Pins** are `MODEL_CHAT`, `MODEL_FAST`, `MODEL_VISION`, `OPENAI_CLASSIFIER_MODEL`, and the owner's `anthropic_model` and `ai_spending_categorisation_model`, read as the owner through `withUser()`.
- **No sub-daily job.** The schedule entry is hourly with London hours [5, 6], which the tick resolves to exactly one slot a day; `schedule.test.ts` asserts the one hit in the 288 slots. `vercel.json` is untouched.
- **The meter.** `createMeteredFetch` only meters `/v1/messages` and the other paid endpoints; `/v1/models` passes straight through, so the daily read costs nothing and cannot be capped.

## Found on the way

- **No route reads the two per-person model choices** in Settings → AI (`anthropic_model`, `ai_spending_categorisation_model`); the page was the only reader, and it offered two retired ids and one that never existed. Every call uses the environment's models. The panel now says what is in use and offers only priced models, and the decision whether the routes should read the person's choice, or the selects go, is Phil's: **MYC-204**.
- **`supabase db push --local` refuses in a lane worktree** once another lane has pushed its migration to the shared local stack: the history holds 0174, 0175 and 0178, which this checkout does not have. 0177 was applied with `psql` in the stack's container (the same door `localSql()` uses) and its version row written, so a later push from the integrated checkout sees it as applied. The migration is idempotent in any case (`if not exists`, `drop policy if exists`).
- **The dev server rebuilt itself in a loop under the end-to-end run, and every rebuild aborted the navigation under test.** Next's file watcher ignores `.git`, `node_modules` and `.next` by name. The end-to-end server builds into `.next-e2e`, which that rule does not match, so each compile's output started the next compile (1,758 compiles in one 30-minute run), and a click on a tab never saw its URL change: the route fetch was thrown away each time and re-issued. Playwright's traces (`e2e/.results`) and the rewritten sessions (`e2e/.auth`) are written mid-test and did the same. `next.config.ts` now hands webpack an ignore rule that covers all of them. The symptom looked like a timing problem in the spec (a tab click reverted, a URL that never changed) and cost most of the lane's time; the spec keeps a small retry on tab clicks as a belt. The dev server's own log must also sit outside the worktree.
- The old 3-column `lib/dashboard/card-registry.ts` model ("width ≥ 2 renders as a full-width spanner above the columns") is still served by `/api/dashboard/layout`, which nothing in the app calls; left as it was.
