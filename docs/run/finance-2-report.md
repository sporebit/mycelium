## What it is

The last §10 item the first part left out: a place for the figures no feed will ever bring (the pension, the house, the mortgage, the cars), a line of net worth over time that sums them with the sheet's daily snapshot, and a monthly item so the pension figure does not go stale. Owner-only, nothing of it ever in a share, nothing of it in a page until amounts are shown.

## How it is put together

- **The line is pure arithmetic** over two lists, with no database in it (`netWorth.ts`): the sheet's days and the holdings' figures. Each is sorted, the set of days is their union, and for each day the newest figure at or before it is taken per holding. That is what makes the unit tests cheap and the e2e assertions exact: the same four seed figures give the same four points every run.
- **Holdings are the owner's by the shape of their rules**, like every finance table since 0111: the row's space is the reader's personal space and nothing else. There is no share path to close because none is open. Tess's figures are hers, Phil's are his, and the API answers 404, not 403, when one asks about the other's holding, so nothing is confirmed to exist.
- **Dates are days, not instants.** A figure is "true on" a calendar day (a statement date, a valuation date), so the as-of column is a date and the API refuses anything that is not a real calendar day (30 February is refused). The default is today in London.
- **The pension item is made in the request that adds the holding**, not by a job, so there is nothing to wait for and nothing to schedule. It is a spawn template in the tickets table, exactly the shape the recurrence job already reads; the lane added no new mechanism, only a template with a marker.
- **Nothing readable is in the page while amounts are hidden.** Names go through `PrivateText`, figures through `Money`, the chart is not rendered at all, and the add button is disabled (a form with a name field would otherwise put the name in the page before it was saved). The one leak found in testing was a remove button whose accessible label carried the holding's name; it now reads "Remove this holding".
- **No new dependency, no new cron, nothing in `vercel.json`.**

## Found on the way

- **`supabase db push --local` refuses in this worktree**: the local history table already records migration 0178 (another lane applied theirs first), and the CLI stops when a remote version is missing from the local directory, even for the local stack. The lane applied 0175 by running the file through `psql` in the container and recording the version in the history table, which is what push would have done. The hosted push, from the integrated tree with every number present, should not hit this.
- **Why investments are shown apart.** The Investments page holds a current price per lot but no history of prices, so there is nothing to draw a line with before today; and the finance sheet's own net-worth figure has always been Phil's full picture, which may already include those holdings. Adding the Investments total to the line would either double-count or draw a flat line that jumps today. The panel states the value and says it is not in the line. If Phil says the sheet does **not** include them, one line in `netWorthView` adds today's figure to today's point; that is his call, listed below.
- **The net-worth series is capped at 36 months** of sheet snapshots by default (the API takes `months`); the holdings' figures are read in full so an old valuation still counts. The first e2e run seeded 2020 dates and saw no points: the dates were outside the window, not missing. The spec now seeds 2024.
- **The "Show financial values" toggle appears twice on the page** (the shell top bar from MYC-191 and the older in-page control), so a test clicking it by role has to pick the first. Not a bug for a person; noted for the next spec.
- **`graphify update .` could not run** (not installed on this PC). The project-side copies of `context.md` and `backlog.md` were not touched (lane rule: the integrator writes those lines).
