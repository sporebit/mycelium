## What it is

A feed of things worth a look (repos, posts, skills, MCP servers, tools, articles, security advisories), each kept once, opened, summarised and given a verdict by the PC's own model, and answered Keep or Skip in the weekly review. No scraper, no paid API, nothing installed by the app.

## How it is put together

- **Two tables (0178), personal-space only** (`finds`, `find_sources`), the 0111 policy shape, `app.adopt_table`, in `entity_groups` and the access registry under studio → `finds`. A find's one key is `(space_id, url)` (unique); a source's is `(space_id, kind, target)`. A find points back at the capture it came from (`capture_id`, set null on delete).
- **Every watcher is a pure parser with the fetch passed in**, so the unit tests read saved replies and the e2e server reads the same files through `FINDS_FIXTURE_DIR` (set in `e2eServerEnv`); no test run reaches GitHub, Hacker News or a feed. A URL's host picks the fixture file (`lib/finds/fixtures.ts`).
- **"Local first" for the verdict.** The job sits on the pc lane for as long as it takes; the page is opened only when the worker claims it (the handler's `prepare`), once, and the text is kept on the find so the cloud route reads the same thing. The cloud is asked only after 36 hours with the PC off, or after the PC's model gave a non-verdict or the job failed twice, six a run, inside the month's cap; the fetch meter (MYC-187) counts the call like every other.
- **The daily turn is safe to run twice.** Each source records its last run (the watchers are read once a London day; `?force=1` re-reads for a check), each find is kept once, each job has a dedupe key, the digest reads the interruptions ledger for the week. Two knockers in the same hour do no harm.
- **The share-in rule is deliberately narrow**: one link, a find host, few words. A link to a shop or a video, or a link inside a longer thought, goes to the classifier like any other capture, where `find` is one kind among the others and the regex heuristic picks it only when the words say neither buy nor watch.
- **Nothing is installed, by either route, ever.** The worker's `npm_audit` runner reads the lockfile and changes nothing; the verdict prompt forbids install advice; the export ends with the record's install advice (read SKILL.md and hooks first, pin, never in an unattended run).
- **No new dependencies.** The feed reader and the HTML stripper are small regex readers, enough for the two feed shapes and for page text in a prompt.

- **The worker's `run()` helper had no `cwd` and no `shell`.** Both were added (defaulting to the old behaviour) so `npm audit` can run in the repo checkout; on Windows npm is a `.cmd` and needs the shell.
- **Hacker News has no stable "topic" API**, so the watcher is three search queries with a points floor; a quiet week gives few finds, which is the point.
- **The interruptions ledger is the digest's memory** (no column added): a `finds_digest` row with a day in the week means sent. If the ledger is ever pruned to under a week, the digest could go twice.

2. Studio → Finds. The shared link is at the top of today with "no verdict yet". With the PC on, within a few minutes it has a verdict badge; open the line and read what, cost, licence, cautions and which project. Say Keep or Skip to it.

4. Export. The Markdown opens with the same columns as the design-resources record, the three verdict lists, and the install advice at the end.
5. Sunday after five: one Telegram message, "This week's finds", with a count and a few lines, no amounts, no "should". Tap through to the week.
